# Implementer map (planned)

Status: planned. Nothing here is implemented. The behaviour is specified in [TECHNICAL_SPEC.md](TECHNICAL_SPEC.md); this file only says where each piece is meant to live and which imports are allowed. Directory names are proposals; the first ticket that creates a directory may adjust it and must update this file and `CLAUDE.md`.

## Modules and allowed imports

| Module | Holds | May import |
|---|---|---|
| `src/trace/` | Scene format v1, replay and trace format v1, canonical serialisation, diagnostic codes | nothing |
| `src/engine/` | Scene validation, fixed-tick stepping, contacts, sensors, sweep, joints, events | `src/trace/` |
| `src/compare/` | Comparison of two traces, tolerances, first-divergence report | `src/trace/` |
| `src/cli/` | Headless runner and compare command | `src/engine/`, `src/trace/`, `src/compare/`, Node standard library |
| `src/server/` | Loopback static server | Node standard library only |
| `src/web/` | Canvas 2D viewer, replay controls, inspector | `src/engine/`, `src/trace/`, `src/compare/` |
| `reference/` | Native Box2D harness; the only code that links Box2D | its own build; writes traces in the `src/trace/` format |

## Rules the layout exists to protect

- The engine is pure: no DOM, no Node API, no clock, no random source. The viewer asks it for ticks and draws them; it never decides simulation time.
- `src/compare/` never imports the engine, and the reference traces are generated by `reference/`, so expected output is independent of the engine under test.
- Only one integrator wires the engine step (contacts, sensors, sweep, joints). Overlap and sweep code and joint code live in separate files and meet only through the frozen step hook.
- Scene and trace formats are versioned; a change to either is a new version with a test that still reads the old one.

## One workflow, end to end

Scene JSON, then `src/trace/` and `src/engine/` validation, then fixed-tick stepping, then an immutable trace, then `src/trace/` canonical bytes, then `src/cli/` (run, compare) or `src/web/` (timeline, selected body, events) through `src/server/`; `src/compare/` checks the same trace against one produced by `reference/`.

## Plan drift from the PRD (recorded 2026-11-22)

The delivery plan differs from `docs/PRD.md` and `docs/TECHNICAL_SPEC.md` in these ways. The PRD and the specification are not edited; ticket B2-06 reconciles the PRD estimate line and the README status when the epic closes.

- **Estimate and ticket count.** The PRD estimates 13-19 engineering hours over six tickets. The plan estimates 25-36 hours over eight: B2-07 (scene contract, caps and diagnostics) and B2-08 (native reference harness) were added to cover specification items no original ticket owned, and the skeleton ticket now includes the toolchain and the local server.
- **Where reference traces are generated.** The specification says traces are generated "on an authorized local host". The plan generates them in CI on `ubuntu-latest` (`.github/workflows/reference.yml`), because no C compiler is installed on the owner's PC. The traces are committed, so the comparison itself runs offline.
- **Commands.** Verification commands in the tickets assume a POSIX shell (Git Bash) or PowerShell 7. Windows PowerShell 5.1 does not run `&&` or the `curl -w` forms as written.
